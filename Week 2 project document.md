# Week 2 – Software Requirements and User Stories

## 1. Week 2 Project Goal

The goal for Week 2 is to improve the original Planora concept by defining what the application needs to do and what users will expect from it.

In Week 1, Planora was introduced as an event-planning application that combines important planning tools into one organized platform. In Week 2, the project is expanded by identifying user needs, software requirements, user stories, and feature priorities.

## 2. User Needs

People planning events may have to keep track of budgets, expenses, guests, vendors, schedules, and tasks at the same time. This information can become difficult to manage when it is spread across different applications, spreadsheets, notes, calendars, and group chats.

Planora is designed to give users one place to organize this information.

The application should be useful for different types of events, including:

- Weddings
- Birthday parties
- Graduation parties
- Baby showers
- Corporate events
- Family gatherings
- Social events

Planora should also be simple enough for someone planning a small event while still providing useful tools for larger events.

## 3. Functional Requirements

Functional requirements describe what Planora should allow users to do.

Planora will allow users to:

- Create a new event.
- Enter an event name, date, time, location, and event type.
- Create an overall event budget.
- Add and track individual expenses.
- View how much of the event budget has been spent and how much remains.
- Create and manage a guest list.
- Send and manage invitations.
- Track guest RSVPs.
- Store vendor names, contact information, services, and costs.
- Create event-planning checklists.
- Add deadlines to important tasks.
- Create an event schedule.
- Receive reminders for upcoming deadlines and tasks.
- Save notes related to an event.
- Collaborate with other users involved in planning the event.

## 4. Non-Functional Requirements

Non-functional requirements describe how the application should perform.

### Usability
Planora should have a simple and organized interface that is easy for users to understand and navigate.

### Performance
The application should load event information quickly and respond to user actions without unnecessary delays.

### Security
Planora should protect users' personal information and event information.

### Reliability
Saved budgets, guest lists, tasks, expenses, and other event information should remain accurate and available to users.

### Accessibility
The application should be designed so that a wide range of users can understand and use its main features.

### Scalability
Planora should be able to support additional users, event types, and features as the application grows.

## 5. User Stories

User stories explain features from the perspective of someone using Planora.

- As a user, I want to create an event so that I can keep all of my event information organized in one place.
- As a user, I want to create a budget so that I can control how much money I spend.
- As a user, I want to track expenses so that I know how much of my budget remains.
- As a user, I want to create a guest list so that I can keep track of everyone I invite.
- As a user, I want to track RSVPs so that I know who is attending my event.
- As a user, I want to save vendor information so that I can easily keep track of the businesses involved with my event.
- As a user, I want to create a checklist so that I know which planning tasks still need to be completed.
- As a user, I want to set deadlines and reminders so that I do not forget important tasks.
- As a user, I want to create an event schedule so that I can keep important activities organized.
- As a user, I want to collaborate with others so that multiple people can help plan the same event.

## 6. Feature Priorities

Not every Planora feature needs to be developed at the same time. Features will be divided into different priorities.

### High Priority

- Event creation
- Budget management
- Expense tracking
- Guest lists
- RSVP tracking
- Planning checklists

These features represent the main functions needed to make Planora useful as an event-planning application.

### Medium Priority

- Vendor management
- Event schedules
- Deadlines
- Reminders
- Notes

These features will provide users with additional organization and planning tools.

### Future Features

- Collaboration between multiple users
- Event templates
- Personalized recommendations
- Advanced budget reports
- Additional customization options

These features can be developed after the main functions of Planora are working.

## 7. Improvements from Week 1

Week 1 established the original idea, vision, scope, target users, and overall goal of Planora.

Week 2 improves the project by defining specific requirements for the application. The original feature list has been expanded into functional requirements, non-functional requirements, and user stories.

The features have also been prioritized to create a clearer development plan. This will help future versions of Planora focus on the most important features first.

## 8. Next Steps

For the next version of Planora, the project will begin focusing on how users will interact with the application.

Future development may include:

- Planning the main screens of the application.
- Creating a navigation structure.
- Designing the user flow.
- Creating an initial interface or prototype.
- Determining how the main Planora features will connect.
